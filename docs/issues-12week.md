# 12주차 GitHub Issues 목록

Issues 탭 → New issue에 제목과 본문을 붙여넣고, 오른쪽 Assignees에 담당자를 지정한다.
브랜치 이름은 담당별로 `feature/menu`, `feature/member`, `feature/discount-payment`, `feature/order-ui`를 쓴다.
PR 설명에 `Closes #번호`를 적으면 병합할 때 이슈가 닫힌다.

## 이슈 1: [A] 메뉴·옵션 코드 리뷰와 SOLID 점검
담당: 조민규 / 브랜치: `feature/menu`

- [ ] `MenuItem`, `Beverage`, `OptionDecorator` 계층을 읽고 각 클래스를 만든 이유를 두 문장으로 정리한다.
- [ ] 새 옵션(예: 얼음 추가)을 추가할 때 어떤 클래스를 수정하는지 확인한다.
- [ ] 리스코프 치환: 자식 클래스가 `price()`는 0 이상이라는 약속을 지키는지 확인한다.
- [ ] 고칠 부분이 있으면 PR로 올리고 README 9장에 기록한다.

## 이슈 2: [B] 회원·등급·포인트 코드 리뷰와 SOLID 점검
담당: 신준서 / 브랜치: `feature/member`

- [ ] `Member`, `GuestMember`, `MembershipGrade` 구현체를 읽고 각 클래스의 역할을 정리한다.
- [ ] 등급을 `enum`이 아니라 인터페이스로 둔 이유를 팀 언어로 적는다. (진행 문서 8장)
- [ ] 인터페이스 분리: `GuestMember`의 빈 메소드가 문제가 없는지 검토한다.
- [ ] 새 등급(예: Platinum)을 추가하는 시연을 준비한다.
